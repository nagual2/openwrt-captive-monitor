# Requirements Document

## Introduction

Исправление проблемы загрузки OpenWrt SDK в Docker образе. Текущая сборка падает при попытке скачать SDK файл, вероятно из-за неправильного формирования URL или имени файла SDK.

## Glossary

- **SDK**: Software Development Kit - набор инструментов OpenWrt для сборки пакетов
- **Docker Image**: Контейнерный образ с предустановленным SDK
- **MUSL**: Легковесная реализация стандартной библиотеки C
- **Build Args**: Аргументы сборки Docker (OPENWRT_VERSION, SDK_TARGET, SDK_SUBTARGET)
- **Dockerfile**: Файл с инструкциями для сборки Docker образа

## Requirements

### Requirement 1

**User Story:** Как разработчик, я хочу, чтобы Docker образ успешно собирался, чтобы использовать его для сборки пакетов OpenWrt

#### Acceptance Criteria

1. WHEN Docker образ собирается THEN система SHALL успешно скачать SDK файл с сервера OpenWrt
2. WHEN система формирует URL для скачивания SDK THEN система SHALL использовать правильный суффикс MUSL для каждой архитектуры
3. WHEN скачивание SDK завершается THEN система SHALL верифицировать контрольную сумму файла
4. WHEN верификация контрольной суммы проходит успешно THEN система SHALL распаковать SDK в /opt/openwrt-sdk
5. WHEN происходит ошибка скачивания THEN система SHALL вывести понятное сообщение об ошибке с URL и деталями

### Requirement 2

**User Story:** Как разработчик, я хочу видеть детальную диагностику при ошибках, чтобы быстро понять причину проблемы

#### Acceptance Criteria

1. WHEN начинается скачивание SDK THEN система SHALL вывести полный URL файла
2. WHEN происходит ошибка curl THEN система SHALL вывести код ошибки и детали
3. WHEN файл не найден на сервере THEN система SHALL вывести список доступных файлов в директории
4. WHEN верификация контрольной суммы не проходит THEN система SHALL вывести ожидаемую и полученную контрольные суммы

### Requirement 3

**User Story:** Как разработчик, я хочу, чтобы сборка была устойчива к временным сетевым проблемам, чтобы не перезапускать её вручную

#### Acceptance Criteria

1. WHEN происходит сетевая ошибка при скачивании THEN система SHALL повторить попытку с экспоненциальной задержкой
2. WHEN скачивание прерывается THEN система SHALL продолжить скачивание с места обрыва
3. WHEN сервер возвращает 5xx ошибку THEN система SHALL повторить запрос до 15 раз
4. WHEN все попытки исчерпаны THEN система SHALL вывести детальную информацию об ошибке и завершиться с ненулевым кодом
