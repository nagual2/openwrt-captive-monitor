# Requirements Document

## Introduction

Данная спецификация описывает удаление поддержки IPv6 из проекта openwrt-captive-monitor. Цель - упростить кодовую базу, удалив функциональность IPv6, которая не используется в текущих сценариях развертывания. Важно, что удаление поддержки IPv6 из приложения не должно влиять на существующие настройки IPv6 на роутере OpenWrt.

## Glossary

- **System**: openwrt-captive-monitor - сервис для обнаружения и обработки captive порталов
- **IPv6 Support**: функциональность в коде для работы с IPv6 адресами, ip6tables правилами и IPv6 DNS
- **Router IPv6 Settings**: системные настройки IPv6 на роутере OpenWrt (network.lan.ip6addr, DHCPv6, и т.д.)
- **Captive Portal**: веб-страница аутентификации, которую пользователь должен пройти для доступа к интернету
- **ip6tables**: утилита для настройки правил фильтрации IPv6 пакетов в Linux
- **busybox httpd**: легковесный HTTP сервер, используемый для редиректа на captive portal
- **dnsmasq**: DNS и DHCP сервер, используемый для перехвата DNS запросов

## Requirements

### Requirement 1

**User Story:** Как разработчик, я хочу удалить весь код, связанный с IPv6, чтобы упростить поддержку и уменьшить сложность кодовой базы.

#### Acceptance Criteria

1. WHEN система запускается THEN система SHALL NOT инициализировать переменные, связанные с IPv6
2. WHEN система обрабатывает конфигурацию THEN система SHALL NOT читать параметры IPv6 из UCI
3. WHEN система запускает HTTP сервер THEN система SHALL использовать только IPv4 (0.0.0.0)
4. WHEN система настраивает firewall правила THEN система SHALL NOT создавать правила ip6tables
5. WHEN система настраивает DNS THEN система SHALL NOT добавлять IPv6 адреса в dnsmasq конфигурацию

### Requirement 2

**User Story:** Как системный администратор, я хочу, чтобы удаление IPv6 поддержки из приложения не влияло на системные настройки IPv6 роутера, чтобы другие сервисы продолжали работать корректно.

#### Acceptance Criteria

1. WHEN приложение удаляется THEN система SHALL NOT изменять network.lan.ip6addr в UCI
2. WHEN приложение останавливается THEN система SHALL NOT удалять IPv6 адреса с интерфейсов
3. WHEN приложение работает THEN система SHALL NOT блокировать IPv6 трафик для других приложений
4. WHEN приложение настраивает firewall THEN система SHALL NOT изменять существующие ip6tables правила других сервисов
5. WHEN приложение работает THEN система SHALL позволять другим сервисам использовать IPv6

### Requirement 3

**User Story:** Как разработчик, я хочу удалить все функции, связанные с IPv6, чтобы уменьшить количество кода для тестирования и поддержки.

#### Acceptance Criteria

1. WHEN код анализируется THEN система SHALL NOT содержать функцию ensure_lan_ipv6
2. WHEN код анализируется THEN система SHALL NOT содержать функцию resolve_portal_ipv6
3. WHEN код анализируется THEN система SHALL NOT содержать функцию is_ipv6
4. WHEN код анализируется THEN система SHALL NOT содержать переменную LAN_IPV6
5. WHEN код анализируется THEN система SHALL NOT содержать переменную HTTPD_IPV6_READY

### Requirement 4

**User Story:** Как разработчик, я хочу удалить все упоминания IPv6 из документации, чтобы пользователи не ожидали поддержки этой функциональности.

#### Acceptance Criteria

1. WHEN документация просматривается THEN система SHALL NOT содержать описание IPv6 функциональности в README
2. WHEN документация просматривается THEN система SHALL NOT содержать примеры конфигурации IPv6
3. WHEN документация просматривается THEN система SHALL NOT содержать инструкции по настройке IPv6
4. WHEN документация просматривается THEN система SHALL содержать явное указание, что IPv6 не поддерживается
5. WHEN changelog просматривается THEN система SHALL содержать запись об удалении IPv6 поддержки

### Requirement 5

**User Story:** Как разработчик, я хочу удалить логирование, связанное с IPv6, чтобы логи были чище и понятнее.

#### Acceptance Criteria

1. WHEN система логирует запуск HTTP сервера THEN система SHALL NOT упоминать IPv6 в сообщениях
2. WHEN система логирует ошибки firewall THEN система SHALL NOT упоминать ip6tables
3. WHEN система логирует предупреждения THEN система SHALL NOT упоминать отсутствие IPv6 адресов
4. WHEN система логирует настройку DNS THEN система SHALL NOT упоминать IPv6 адреса
5. WHEN система логирует информацию THEN все сообщения SHALL быть связаны только с IPv4

### Requirement 6

**User Story:** Как тестировщик, я хочу удалить тесты, связанные с IPv6, чтобы сократить время выполнения тестов и упростить тестовую инфраструктуру.

#### Acceptance Criteria

1. WHEN тесты запускаются THEN система SHALL NOT выполнять тесты функций IPv6
2. WHEN тесты анализируются THEN система SHALL NOT содержать моки для ip6tables
3. WHEN тесты анализируются THEN система SHALL NOT содержать тестовые данные с IPv6 адресами
4. WHEN тесты запускаются THEN система SHALL проверять только IPv4 функциональность
5. WHEN coverage анализируется THEN система SHALL показывать 100% покрытие без IPv6 кода

### Requirement 7

**User Story:** Как пользователь, я хочу, чтобы приложение работало корректно после удаления IPv6 поддержки, используя только IPv4.

#### Acceptance Criteria

1. WHEN captive portal активируется THEN система SHALL перехватывать HTTP трафик через IPv4
2. WHEN DNS запросы перехватываются THEN система SHALL обрабатывать только IPv4 DNS запросы
3. WHEN пользователь открывает браузер THEN система SHALL редиректить на captive portal через IPv4
4. WHEN captive portal деактивируется THEN система SHALL удалять только IPv4 правила iptables
5. WHEN система работает THEN все функции SHALL работать корректно без IPv6 кода

### Requirement 8

**User Story:** Как разработчик, я хочу обновить конфигурационные файлы, удалив опции IPv6, чтобы пользователи не пытались настроить несуществующую функциональность.

#### Acceptance Criteria

1. WHEN UCI конфигурация анализируется THEN система SHALL NOT содержать опцию lan_ipv6
2. WHEN конфигурационные примеры просматриваются THEN система SHALL NOT содержать примеры с IPv6 адресами
3. WHEN документация конфигурации просматривается THEN система SHALL NOT описывать параметры IPv6
4. WHEN пользователь читает конфигурацию THEN система SHALL ясно указывать, что поддерживается только IPv4
5. WHEN существующая конфигурация с IPv6 параметрами загружается THEN система SHALL игнорировать эти параметры без ошибок
