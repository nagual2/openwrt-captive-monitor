# Исследование проблемы с procd

**Дата начала:** 28 ноября 2025  
**Статус:** В процессе  
**Приоритет:** Критичный

## Описание проблемы

Сервис `captive-monitor` не запускается через procd при вызове `/etc/init.d/captive-monitor start`, хотя ручной запуск скрипта работает корректно.

## Гипотезы

### Гипотеза 1: Проблема с вызовами procd функций

**Предположение:** Init скрипт неправильно вызывает procd функции или не все параметры установлены корректно.

**Тест:**
1. Добавить debug логирование в каждый вызов procd функции
2. Проверить логи после запуска сервиса
3. Убедиться что все функции вызываются в правильном порядке

**Ожидаемый результат:**
- Логи покажут какие функции вызываются
- Можно будет увидеть где происходит сбой

**Статус:** ⏳ В процессе (добавлено debug логирование)

### Гипотеза 2: Проблема с переменными окружения

**Предположение:** procd не передает переменные окружения в процесс, или скрипт зависит от переменных которые не установлены.

**Тест:**
1. Создать минимальный init скрипт без переменных окружения
2. Запустить и проверить работает ли
3. Постепенно добавлять переменные и проверять

**Ожидаемый результат:**
- Минимальный скрипт должен работать
- Можно будет определить какая переменная вызывает проблему

**Статус:** ⏳ В процессе (создан minimal init скрипт)

### Гипотеза 3: Проблема с правами доступа

**Предположение:** procd запускает процесс с неправильными правами, или файлы имеют неправильные права (UID 1001).

**Тест:**
1. Проверить права на все файлы
2. Изменить владельца на root:root
3. Проверить права на исполнение

**Ожидаемый результат:**
- Все файлы должны иметь права 0755 и владельца root:root
- Если проблема в правах - изменение должно помочь

**Статус:** ⏳ Запланировано

### Гипотеза 4: Проблема с путями

**Предположение:** procd использует другой PATH, скрипт не находит необходимые команды.

**Тест:**
1. Добавить в скрипт явный PATH
2. Использовать абсолютные пути для всех команд
3. Проверить доступность команд через `which`

**Ожидаемый результат:**
- Скрипт должен работать с явным PATH
- Логи покажут какие команды не найдены

**Статус:** ⏳ Запланировано

### Гипотеза 5: Проблема с load_config

**Предположение:** Функция `load_config` возвращает ошибку при запуске через procd, UCI недоступен в момент запуска.

**Тест:**
1. Добавить логирование в `load_config`
2. Проверить возвращаемое значение
3. Попробовать запустить без вызова `load_config`

**Ожидаемый результат:**
- Логи покажут успешность загрузки конфигурации
- Если проблема в UCI - скрипт без `load_config` должен работать

**Статус:** ⏳ Запланировано

### Гипотеза 6: Проблема с respawn параметрами

**Предположение:** Параметры respawn вызывают проблему, procd не может правильно обработать их.

**Тест:**
1. Убрать `procd_set_param respawn`
2. Запустить сервис
3. Проверить работает ли

**Ожидаемый результат:**
- Сервис должен запуститься без respawn
- Если проблема в respawn - можно будет скорректировать параметры

**Статус:** ⏳ Запланировано

### Гипотеза 7: Проблема со stdout/stderr

**Предположение:** Перенаправление stdout/stderr вызывает проблему.

**Тест:**
1. Убрать `procd_set_param stdout 1` и `stderr 1`
2. Запустить сервис
3. Проверить работает ли

**Ожидаемый результат:**
- Сервис должен запуститься без перенаправления
- Логи могут не появляться, но процесс должен быть

**Статус:** ⏳ Запланировано

## Известные особенности procd

### Документация procd

- [OpenWrt procd documentation](https://openwrt.org/docs/guide-developer/procd-init-scripts)
- [procd source code](https://git.openwrt.org/?p=project/procd.git)

### Типичные ошибки

1. **Забыть вызвать procd_close_instance** - сервис не зарегистрируется
2. **Неправильный порядок вызовов** - procd может игнорировать параметры
3. **Отсутствие USE_PROCD=1** - скрипт не будет использовать procd
4. **Неправильный command** - процесс не запустится

### Требования к init скриптам

1. Должен быть исполняемым (chmod +x)
2. Должен иметь START и STOP переменные
3. Должен иметь USE_PROCD=1 для использования procd
4. Должен определить start_service() функцию
5. Должен вызвать procd_open_instance и procd_close_instance
