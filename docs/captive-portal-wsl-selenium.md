# Авторизация captive порталов через WSL (SOCKS Proxy)

## Обзор

`captive_portal_wsl_selenium.py` - основной скрипт для авторизации на captive порталах (в частности `conn4.com`) через WSL, использующий SOCKS прокси для перенаправления трафика.

В отличие от устаревших методов, этот скрипт **не требует** `sudo` прав и не изменяет системную таблицу маршрутизации. Весь трафик браузера изолированно направляется через SOCKS туннель (обычно SSH Dynamic Port Forwarding).

## Возможности

- ✅ **Безопасность**: Работает без `sudo` и не затрагивает сетевые настройки WSL/Windows.
- ✅ **Изоляция**: Использует SOCKS5 прокси для браузера.
- ✅ **Conn4.com**: Специализированная логика для порталов типа `conn4.com` (iframe, JS-инъекции).
- ✅ **Отладка**:
  - Создание JSON-дампов состояния (requests, traces).
  - Скриншоты этапов.
  - Перехват сетевых запросов (Fetch/XHR).

## Требования

### Системные требования
- WSL 2
- Google Chrome в WSL
- Запущенный SOCKS сервер (например, через `ssh -D`)

### Переменные окружения
Скрипт использует следующие переменные (или значения по умолчанию):

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `NOJS_SOCKS_PORT` | Порт локального SOCKS прокси | `10800` |
| `OPENWRT_SSH_HOST` | Хост для проверки SSH | `dev-openwrt` |
| `OPENWRT_SSH_USER` | Пользователь SSH | `root` |

### Python зависимости
```bash
pip3 install selenium webdriver-manager
```

## Использование

### Запуск
```bash
# Убедитесь, что SOCKS прокси запущен (например, на порту 10800)
# ssh -D 10800 root@dev-openwrt -N &

# Запуск скрипта
wsl python3 tools/captive_portal_wsl_selenium.py
```

### Принцип работы
1. **Проверка окружения**: Проверяет доступность роутера и наличие слушателя на порту SOCKS.
2. **Настройка Chrome**: Запускает Chrome в headless режиме с аргументом `--proxy-server=socks5://127.0.0.1:<PORT>`.
3. **Детектирование портала**: Пытается перейти на `http://www.msftconnecttest.com/redirect` и отслеживает редиректы.
4. **Взаимодействие**:
   - Ищет специфичные для `conn4.com` элементы (iframe, кнопки "Get Free Wi-Fi").
   - Внедряет JS для обхода проверок и сбора метрик.
   - Эмулирует нажатие кнопки подключения.
5. **Анализ**: Сохраняет скриншоты и дампы для анализа в случае успеха или неудачи.

## Отладка

### Артефакты
В процессе работы создаются файлы:
- `conn4_selenium_debug.log` - подробный лог работы.
- `conn4_portal_page.png` - скриншот страницы портала.
- `conn4_debug_*.json` - дампы состояния (DOM, запросы).
