## 🚀 Getting Started

### Development Setup
For complete development environment setup, see the main [Contributing Guide](CONTRIBUTING.md).

### Quick Start Checklist
1. [Fork the repository](https://github.com/nagual2/openwrt-captive-monitor/fork)
2. [Clone your fork](https://docs.github.com/en/repositories/creating-and-managing-repositories/cloning-a-repository)
3. Set up development environment (see Contributing Guide)
4. Create a feature branch
5. Make your changes
6. Submit a pull request

## 📝 Contribution Types

### Bug Reports
- Use the [Bug Report template](../../../.github/ISSUE_TEMPLATE/bug_report.md)
- Include detailed reproduction steps
- Provide system information and logs

### Feature Requests
- Use the [Feature Request template](../../../.github/ISSUE_TEMPLATE/feature_request.md)
- Describe the problem you're solving
- Explain the proposed solution

### Documentation
- Report documentation issues with the [Documentation Issue template](../../../.github/ISSUE_TEMPLATE/docs.yml)
- Submit documentation improvements via pull requests

### Code Contributions
- Follow the [development guidelines](CONTRIBUTING.md#development-guidelines)
- Ensure all tests pass
- Update documentation as needed

## 🔧 Development Guidelines

### Code Style
- Follow project coding standards
- Use conventional commit messages
- Write clear, documented code

### Testing
- Write tests for new functionality
- Ensure existing tests pass
- Test on multiple platforms when possible

### Documentation
- Update relevant documentation
- Include usage examples
- Document API changes

## 🔄 Pull Request Process

### Before Submitting
1. [Create an issue](https://github.com/nagual2/openwrt-captive-monitor/issues/new/choose) to discuss major changes
2. Fork the repository and create a feature branch
3. Make your changes following the guidelines
4. Test thoroughly
5. Update documentation

### Submitting PRs
1. Use clear, descriptive titles
2. Link to related issues
3. Include screenshots for UI changes
4. Request appropriate reviewers

### After Submission
- Respond to review comments promptly
- Make requested changes
- Keep the PR up to date with main

# Документация по участию в проекте

Этот раздел содержит документацию для участников проекта openwrt-captive-monitor.

## 📋 Основная документация

### Руководства по вкладу
- [Руководство по вкладу](CONTRIBUTING.md) — Полное руководство по внесению изменений и процессу разработки
- [Кодекс поведения](CODE_OF_CONDUCT.md) — Правила и ожидания от поведения в сообществе

## 🚀 Начало работы

### Настройка окружения разработки
Полное руководство по настройке окружения разработки см. в основном [Руководстве по вкладу](CONTRIBUTING.md).

### Чек‑лист быстрого старта
1. [Сделайте форк репозитория](https://github.com/nagual2/openwrt-captive-monitor/fork)
2. [Клонируйте свой форк](https://docs.github.com/en/repositories/creating-and-managing-repositories/cloning-a-repository)
3. Настройте окружение разработки (см. Руководство по вкладу)
4. Создайте feature‑ветку
5. Внесите изменения
6. Отправьте pull request

## 📝 Типы вклада

### Отчёты об ошибках
- Используйте [шаблон отчёта об ошибке](../../../.github/ISSUE_TEMPLATE/bug_report.md)
- Включайте детальные шаги воспроизведения
- Предоставляйте информацию о системе и логи

### Запросы функций
- Используйте [шаблон запроса функции](../../../.github/ISSUE_TEMPLATE/feature_request.md)
- Опишите проблему, которую вы решаете
- Объясните предлагаемое решение

### Документация
- Сообщайте о проблемах в документации с помощью [шаблона задачи по документации](../../../.github/ISSUE_TEMPLATE/docs.yml)
- Отправляйте улучшения документации через pull request

### Вклад в код
- Соблюдайте [рекомендации по разработке](CONTRIBUTING.md#development-guidelines)
- Убедитесь, что все тесты проходят
- Обновляйте документацию по мере необходимости

## 🔧 Рекомендации по разработке

### Стиль кода
- Соблюдайте стандарты кодирования проекта
- Используйте сообщения коммитов в формате Conventional Commits
- Пишите понятный и документированный код

### Тестирование
- Пишите тесты для новой функциональности
- Убедитесь, что существующие тесты проходят
- По возможности тестируйте на нескольких платформах

### Документация
- Обновляйте соответствующую документацию
- Добавляйте примеры использования
- Документируйте изменения API

## 🔄 Процесс pull request

### Перед отправкой
1. [Создайте задачу](https://github.com/nagual2/openwrt-captive-monitor/issues/new/choose), чтобы обсудить крупные изменения
2. Сделайте форк репозитория и создайте feature‑ветку
3. Внесите изменения в соответствии с рекомендациями
4. Тщательно протестируйте
5. Обновите документацию

### Отправка PR
1. Используйте понятные и описательные заголовки
2. Связывайте PR с соответствующими задачами
3. При изменениях UI прикладывайте скриншоты
4. Запрашивайте подходящих рецензентов

### После отправки
- Оперативно отвечайте на комментарии рецензентов
- Вносите запрошенные изменения
- Поддерживайте ветку в актуальном состоянии относительно main
